## 1. Theoretical Foundations

### 1.1 Sequential Processing Paradigms: RNN to Transformer Evolution

The assignment demonstrates the architectural evolution from recurrent to attention-based processing. This progression illuminates fundamental differences in how temporal dependencies are modeled:

**RNN Paradigm:**
- **Sequential Bottleneck**: Information flows through a single hidden state vector, creating computational dependencies
- **Vanishing Gradients**: Long sequences suffer from diminishing gradient signals
- **Limited Parallelization**: Sequential nature prevents efficient GPU utilization

**Transformer Paradigm:**
- **Parallel Processing**: All positions processed simultaneously through self-attention
- **Direct Connections**: Every position can attend to every other position directly
- **Scalability**: Computational complexity scales quadratically with sequence length but enables massive parallelization

### 1.2 Multi-Head Attention: Theoretical Foundation

The multi-head attention mechanism implements parallel attention computations, each focusing on different representation subspaces:

```
Attention(Q,K,V) = softmax(QK^T / √d_k)V
MultiHead(Q,K,V) = Concat(head_1, ..., head_h)W^O
where head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)
```

**Critical Insight**: Each head operates in a d_k = d_model/h dimensional subspace, allowing the model to attend to information from different representation perspectives simultaneously.

### 1.3 Vision Transformer Paradigm Shift

ViT introduces a radical departure from CNN-based vision models:

**Patch Embedding Strategy:**
- Images divided into fixed-size patches (16×16 typically)
- Each patch treated as a "token" in transformer vocabulary
- Spatial relationships learned through positional embeddings

**Architectural Innovation:**
The implementation introduces ConvStem as an alternative to standard patch embedding, providing better inductive biases for small datasets.

## 2. Mathematical and Algorithmic Core

### 2.1 Multi-Head Attention Mathematical Framework

The implementation reveals sophisticated tensor manipulation patterns:

**Dimension Transformation Pipeline:**
```
Input: [B, L, d_model] 
→ QKV Projection: [B, L, 3*d_model]
→ Reshape: [B, L, 3, num_heads, d_k]
→ Permute: [3, B, num_heads, L, d_k]
→ Split: Q,K,V each [B, num_heads, L, d_k]
```

**Attention Computation:**
```python
# Scaled dot-product attention with efficient batched computation
scores = torch.matmul(Q, K.transpose(-2, -1)) / sqrt(d_k)
if mask: scores = scores.masked_fill(mask == 0, -1e9)
attn_weights = softmax(scores, dim=-1)
output = torch.matmul(attn_weights, V)
```

**Critical Design Decision**: The combined QKV projection (`nn.Linear(dim, 3*dim)`) offers significant computational advantages:
- Single matrix multiplication vs. three separate operations
- Better memory locality and cache utilization
- Reduced parameter management complexity

### 2.2 Positional Encoding: Sinusoidal vs. Learned

The implementation demonstrates both approaches:

**Sinusoidal Encoding (PA3 standard):**
```
PE(pos, 2i) = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

**Learned Positional Embeddings (ViT):**
```python
self.pos_embed = nn.Parameter(torch.zeros(1, num_patches + 1, embed_dim))
```

**Trade-off Analysis:**
- **Sinusoidal**: Generalizes to unseen sequence lengths, deterministic
- **Learned**: Adapts to specific tasks and data patterns, requires training

### 2.3 Vision Transformer Mathematical Innovations

**ConvStem Architecture:**
```python
# Progressive feature extraction before patch tokenization
Conv2d(3→64, k=3, s=1, p=1) → BatchNorm → GELU
Conv2d(64→64, k=3, s=1, p=1) → BatchNorm → GELU  
Conv2d(64→embed_dim, k=patch_size, s=patch_size)
```

This provides superior inductive bias compared to linear projection, particularly beneficial for small datasets like CIFAR-10.

**LayerScale Innovation:**
```python
self.gamma = nn.Parameter(init_value * torch.ones(dim))
output = self.gamma * attention_output
```

Enables stable training of very deep transformers by controlling residual branch contributions.

### 3.3 Vision Transformer Architectural Innovations

**DropPath (Stochastic Depth):**
```python
def forward(self, x):
    if self.drop_prob == 0. or not self.training:
        return x
    keep_prob = 1 - self.drop_prob
    shape = (x.shape[0],) + (1,) * (x.ndim - 1)
    random_tensor = keep_prob + torch.rand(shape, device=x.device)
    return x.div(keep_prob) * random_tensor.floor_()
```

**Engineering Insight**: Unlike standard dropout which randomly zeros individual neurons, DropPath stochastically drops entire residual paths, providing better regularization for deep networks.

```python
mixed_x = lam * x + (1 - lam) * x[index, :]
loss = lam * criterion(pred, y_a) + (1 - lam) * criterion(pred, y_b)
```

Provides superior generalization for small datasets by creating synthetic training examples.

# PA4: Sequence-to-Sequence Transformer - Advanced Generation Techniques and Decoder Architecture

## Executive Summary

This document provides comprehensive technical analysis of PA4's sequence-to-sequence transformer implementation for French-to-English machine translation. The assignment represents a critical architectural evolution from encoder-only models to encoder-decoder frameworks, introducing sophisticated challenges in autoregressive generation, cross-attention mechanisms, and the fundamental training-inference paradigm dichotomy.

**Key Technical Achievements:**
- Custom transformer decoder with dual attention mechanisms (self + cross)
- Training loss: ~0.9, Testing loss: <2.2 on filtered French-English dataset
- Sophisticated causal masking preventing information leakage during training
- Autoregressive generation with early stopping and sequence management
- Parameter constraints: <3.5M total, <0.8M encoder, <1.2M decoder

**Critical Innovation**: Implementation demonstrates the architectural complexity difference between classification (PA3) and generation tasks, particularly the training-inference mismatch inherent in autoregressive models.

## 1. Theoretical Foundations

### 1.1 Encoder-Decoder Paradigm Evolution

The sequence-to-sequence architecture introduces fundamental complexity beyond encoder-only transformers:

**Information Flow Architecture:**
```
Source Language → Encoder → Rich Context Representations
                              ↓
Target Sequence → Decoder → Cross-Attention Bridge → Generated Sequence
      ↑                         ↑
Causal Self-Attention    Encoder Memory Access
```

**Paradigm Shift**: Unlike classification where all positions are processed simultaneously, generation requires respecting temporal causality - each position can only condition on previous positions and encoder context.

### 1.2 Dual Attention Mechanism Theory

The decoder implements two distinct attention patterns:

**Self-Attention (Causal):**
- **Purpose**: Model dependencies within target sequence
- **Constraint**: Position i can only attend to positions ≤ i
- **Implementation**: Causal masking with -∞ values

**Cross-Attention:**
- **Purpose**: Align target positions with relevant source content
- **Freedom**: Each decoder position can attend to all encoder positions
- **Mechanism**: Decoder queries attend to encoder key-value pairs

**Mathematical Foundation:**
```
Self-Attention:  Attention(Q_dec, K_dec, V_dec) + Causal_Mask
Cross-Attention: Attention(Q_dec, K_enc, V_enc) [No masking]
```

### 1.3 Training-Inference Dichotomy

**Core Problem**: Fundamental mismatch between training and deployment:

**Training (Teacher Forcing):**
- All target positions processed in parallel
- Ground truth tokens provided at each step
- Model never experiences its own errors
- Causal masking simulates sequential constraint

**Inference (Autoregressive):**
- Sequential generation, one token at a time
- Model conditions on its own previous predictions
- Error propagation across time steps
- No ground truth available during generation

This necessitates separate `forward_train` and `forward_test` implementations, a unique requirement in generation tasks.

## 2. Mathematical and Algorithmic Core

### 2.1 Transformer Decoder Cell Architecture

The decoder cell implements a sophisticated three-stage computation:

**Stage 1 - Masked Self-Attention:**
```
Q, K, V = Linear_projections(decoder_input)
Scores = (Q @ K^T) / √d_k
Masked_Scores = Scores + Causal_Mask  # -∞ for forbidden positions
Attention_Weights = Softmax(Masked_Scores)
Self_Attended = Attention_Weights @ V
```

**Stage 2 - Cross-Attention:**
```
Q_dec = Linear_projection(self_attended_output)
K_enc, V_enc = encoder_outputs
Cross_Scores = (Q_dec @ K_enc^T) / √d_k  # No masking
Cross_Attention = Softmax(Cross_Scores) @ V_enc
```

**Stage 3 - Feed-Forward Network:**
```
FFN(x) = Linear_2(ReLU(Linear_1(x)))
```

**Post-Normalization Pattern:**
```python
# Residual connections with post-norm
x = LayerNorm(x + self_attention(x))
x = LayerNorm(x + cross_attention(x, encoder_memory))
x = LayerNorm(x + ffn(x))
```

### 2.2 Causal Masking Mathematics

**Mask Construction Algorithm:**
```python
def create_causal_mask(sequence_length):
    # Upper triangular matrix with diagonal = 0
    mask = torch.triu(torch.ones(sequence_length, sequence_length), diagonal=1)
    return mask == 0  # Convert to boolean: True = allowed, False = forbidden
```

**Applied Masking Logic:**
```python
attention_scores = (Q @ K.transpose(-2, -1)) / math.sqrt(d_k)
if causal_mask is not None:
    # Add large negative values to forbidden positions
    attention_scores = attention_scores.masked_fill(causal_mask == False, -1e9)
attention_weights = F.softmax(attention_scores, dim=-1)
```

**Critical Insight**: The mask is applied before softmax normalization, ensuring forbidden positions receive near-zero attention weights after exponential normalization.

### 2.3 Autoregressive Generation Algorithm

**Training Algorithm (Parallel):**
```python
def forward_train(self, src, tgt):
    # Encode source sequence
    encoder_output = self.encoder(embed_and_position(src))
    
    # Prepare target: prepend SOS token
    tgt_input = torch.cat([SOS_tokens, tgt], dim=1)
    tgt_embedded = embed_and_position(tgt_input)
    
    # Decode with causal masking
    causal_mask = create_causal_mask(tgt_embedded.size(1))
    decoder_output = self.decoder(tgt_embedded, encoder_output, causal_mask)
    
    # Project to vocabulary and compute loss
    logits = self.output_projection(decoder_output)
    return F.log_softmax(logits[:, :-1], dim=-1)  # Exclude last position
```

**Inference Algorithm (Sequential):**
```python
def forward_test(self, src):
    encoder_output = self.encoder(embed_and_position(src))
    
    # Initialize with SOS token
    generated_sequence = torch.tensor([[SOS_TOKEN]])
    
    for step in range(MAX_LENGTH):
        # Embed current sequence
        current_embedded = embed_and_position(generated_sequence)
        
        # Create causal mask for current length
        causal_mask = create_causal_mask(current_embedded.size(1))
        
        # Decode current sequence
        decoder_output = self.decoder(current_embedded, encoder_output, causal_mask)
        
        # Predict next token
        next_logits = self.output_projection(decoder_output[:, -1:, :])
        next_token = torch.argmax(next_logits, dim=-1)
        
        # Append prediction and check for end
        generated_sequence = torch.cat([generated_sequence, next_token], dim=1)
        if next_token == EOS_TOKEN:
            break
    
    return generated_sequence
```

```python
    src_embed = self.src_token_embed(src) * math.sqrt(self.embed_dim)
```

## 4. Critical Design Decisions and Engineering Trade-offs

### 4.1 Masking Strategy Implementation

**PyTorch MultiheadAttention Mask Semantics:**
```python
# Critical implementation detail: mask polarity
# PyTorch expects: True = attend, False = ignore
# But create_causal_mask returns: True = allow, False = forbid
# Solution: Careful mask handling in forward pass

if tgt_mask is not None:
    # Negate mask for PyTorch MultiheadAttention
    negated_mask = ~tgt_mask
    self_attn_output, _ = self.self_attention(
        query=x, key=x, value=x,
        attn_mask=negated_mask,
        is_causal=False  # Explicit mask provided
    )
```

**Design Decision Rationale**: Explicit masking provides more control than PyTorch's implicit `is_causal=True`, enabling debugging and educational clarity.

### 4.2 Positional Encoding Strategy

**Sinusoidal vs. Learned Embeddings:**
The implementation uses sinusoidal encoding:

```python
def forward(self, x):
    seq_len, input_dim = x.shape[1], x.shape[2]
    
    # Create position indices and dimension indices
    position = torch.arange(seq_len).unsqueeze(1)
    div_term = torch.exp(-math.log(10000.0) * torch.arange(0, input_dim, 2) / input_dim)
    
    # Apply sinusoidal functions
    pe = torch.zeros(seq_len, input_dim)
    pe[:, 0::2] = torch.sin(position * div_term)  # Even dimensions
    pe[:, 1::2] = torch.cos(position * div_term)  # Odd dimensions
    
    return x + pe.unsqueeze(0).to(x.device)
```

**Strategic Advantage**: Sinusoidal encoding generalizes to sequences longer than training examples, crucial for translation where target length is unpredictable.

### 4.3 Loss Computation Strategy

**Sequence Alignment Challenge:**
```python
# Training sequence alignment:
# Input:  [SOS, w1, w2, w3]     (length N+1)
# Target: [w1, w2, w3, EOS]     (length N+1)
# Prediction excludes final position, target excludes SOS

predictions = decoder_output[:, :-1, :]  # Shape: [B, N, V]

loss = nn.NLLLoss()(predictions.reshape(-1, vocab_size), targets.reshape(-1))
```

**Implementation Insight**: The off-by-one alignment ensures each position predicts the next token while maintaining causal constraints.

```python
class BeamSearch:
    def __init__(self, beam_size=5, max_length=50):
        self.beam_size = beam_size
        self.max_length = max_length
    
    def search(self, model, src_sequence):
        # Maintain beam_size hypotheses
        beams = [Hypothesis(tokens=[SOS_TOKEN], score=0.0)]
        
        for step in range(self.max_length):
            candidates = []
            for beam in beams:
                if beam.tokens[-1] == EOS_TOKEN:
                    candidates.append(beam)
                    continue
                
                # Get next token probabilities
                logits = model.forward_step(src_sequence, beam.tokens)
                top_k_probs, top_k_indices = torch.topk(F.softmax(logits), self.beam_size)
                
                # Create new hypotheses
                for prob, token in zip(top_k_probs, top_k_indices):
                    new_hypothesis = beam.extend(token, math.log(prob))
                    candidates.append(new_hypothesis)
            
            # Keep top beam_size candidates
            beams = sorted(candidates, key=lambda x: x.score, reverse=True)[:self.beam_size]
        
        return beams[0]  # Return best hypothesis
```

## 1. The Generation Paradigm: A Conceptual Revolution

The transition from PA3's classification task to PA4's generation represents more than an architectural change—it embodies a fundamental shift in how we conceptualize machine intelligence. Classification asks "what is this?" while generation asks "what comes next?" This seemingly simple difference conceals profound computational and philosophical implications.

**The Recognition Paradigm** operates in a closed world where all possible answers exist within a finite label space. The model's task is selection among predetermined options, analogous to multiple-choice reasoning. Success metrics are binary: correct or incorrect classifications with clear ground truth.

**The Generation Paradigm** opens infinite possibility spaces where the model must construct novel sequences token by token. Unlike classification's discrete decision points, generation requires sustained coherence across extended temporal horizons. ### 1.2 The Temporal Causality Problem

Generation tasks expose a fundamental challenge largely invisible in classification: the requirement to respect temporal causality while learning from complete sequences. The causal masking mechanism emerges as more than a technical constraint; it becomes a cognitive architecture that enforces temporal reasoning. **Cognitive Analogy**: Consider how humans learn language generation. Causal masking replicates this constraint digitally.

The encoder-decoder framework mirrors fundamental cognitive processes observed in human language translation and comprehension. **The Encoding Phase** transforms sequential source tokens into a parallel representation space where all information exists simultaneously. **The Decoding Phase** faces the creative challenge of transforming timeless understanding into temporal expression. Each decoder step must balance fidelity to source content (through cross-attention) with coherent continuation of the target sequence (through self-attention).

## 3. The Training-Inference Paradigm Mismatch

### 3.1 The Fundamental Asymmetry Problem

One of the most profound insights from PA4 concerns the inherent asymmetry between training and deployment in generation tasks. This asymmetry reveals deep challenges in how machines learn temporal behaviors.

**Training Reality**: Models observe complete target sequences during training, using teacher forcing to provide ground truth context at every step. This creates an artificial scenario where the model never experiences its own mistakes or uncertainty during learning.

**Deployment Reality**: Models must generate sequences autoregressively, conditioning each prediction on their own previous outputs. Every error potentially cascades through subsequent generations, creating error propagation patterns never encountered during training.

**The Exposure Bias Phenomenon**: This mismatch means models develop expectations about input quality (perfect ground truth) that deployment cannot satisfy (imperfect model outputs). The resulting performance degradation represents more than a technical challenge—it reveals fundamental limitations in how we currently approach sequential learning.

### 3.2 Implications for Machine Learning Theory

The training-inference mismatch in sequence generation tasks exposes broader questions about machine learning methodology. Most supervised learning assumes that training and deployment distributions remain constant, but generation tasks violate this assumption by design.

**Distribution Shift by Construction**: The model's own outputs during inference create a fundamentally different input distribution than training data. This isn't accidental distribution drift—it's an inherent property of autoregressive generation.

**Temporal Error Propagation**: Unlike classification errors which are isolated to single predictions, generation errors compound across time steps. A single incorrect token can alter the trajectory of an entire sequence, creating cascading failures never observed during training.

**The Need for New Training Paradigms**: These insights suggest that traditional teacher forcing, while computationally efficient, may be fundamentally inadequate for robust generation systems. Alternative approaches like scheduled sampling or reinforcement learning become not just optimizations but necessities for addressing the paradigm mismatch.

# PA5: Diffusion Models - Technical Implementation and Advanced Architecture Analysis

## Executive Summary

This document provides comprehensive technical analysis of PA5's Denoising Diffusion Probabilistic Models (DDPM) implementation for grayscale image generation on MNIST subset (digits 0 and 1). The assignment represents a paradigm shift from discriminative models (classification/generation) to generative models based on iterative denoising processes, introducing sophisticated mathematical frameworks and novel architectural components.

**Key Technical Achievements:**
- Custom UNet architecture with skip connections and multi-scale processing
- DDPM implementation supporting both x₀ and ε (epsilon) prediction variants
- Advanced regularization techniques including DropPath and LayerScale
- Sophisticated training pipeline with noise scheduling and iterative denoising
- Parameter-efficient design optimized for educational constraints (<15M parameters)

**Critical Innovation**: Implementation demonstrates the mathematical elegance of diffusion processes as generative models, leveraging iterative refinement rather than single-step generation for high-quality image synthesis.

## 1. Theoretical Foundations

### 1.1 Diffusion Process Mathematical Framework

Diffusion models represent a fundamental departure from traditional generative approaches (GANs, VAEs) by modeling the data generation process as reverse diffusion, mimicking physical phenomena observed in thermodynamics and statistical mechanics.

**Forward Diffusion Process:**
The forward process systematically adds Gaussian noise to data over T timesteps:
```
q(x₁:ₜ|x₀) = ∏ᵢ₌₁ᵀ q(xᵢ|xᵢ₋₁)
q(xᵢ|xᵢ₋₁) = N(xᵢ; √αᵢxᵢ₋₁, (1-αᵢ)I)
```

**Reverse Process (Generation):**
The reverse process learns to denoise, generating data by iteratively removing noise:
```
pθ(x₀:ₜ₋₁|xₜ) = ∏ᵢ₌₁ᵀ pθ(xᵢ₋₁|xᵢ)
pθ(xᵢ₋₁|xᵢ) = N(xᵢ₋₁; μθ(xᵢ,t), σₜ²I)
```

**Key Mathematical Insight**: The forward process has a closed-form solution enabling direct sampling at any timestep t without sequential computation:
```
q(xₜ|x₀) = N(xₜ; √ᾱₜx₀, (1-ᾱₜ)I)
where ᾱₜ = ∏ᵢ₌₁ᵗ αᵢ
```

### 1.2 Two Prediction Paradigms: x₀ vs ε Variants

The DDPM framework supports two mathematically equivalent but practically different prediction targets:

**x₀ Prediction Variant:**
The model directly predicts the original clean image:
```
Loss = E[||x₀ - f_θ(xₜ, t)||²]
Denoising: x₀_pred = f_θ(xₜ, t)
```

**ε Prediction Variant:**
The model predicts the noise component:
```
Loss = E[||ε - f_θ(xₜ, t)||²]
Denoising: x₀_pred = (xₜ - √(1-ᾱₜ)ε_pred) / √ᾱₜ
```

**Theoretical Equivalence**: Both variants optimize the same variational lower bound but differ in training dynamics and numerical stability properties.

### 1.3 Noise Scheduling Theory

The noise schedule {αₜ}ᵀₜ₌₁ controls the rate of information destruction during forward diffusion:

**Linear Schedule Implementation:**
```
αₜ = (α₁ - αₜ) × t/T + αₜ
```

**Critical Design Considerations:**
- **α₁ (small values)**: Controls initial noise level; too small causes training instability
- **αₜ (large values)**: Controls final noise level; too large prevents complete noise saturation
- **T (timesteps)**: Balances generation quality vs computational cost

## 2. UNet Architecture for Diffusion Models

### 2.1 UNet Design Philosophy for Image Generation

The UNet architecture serves as the backbone for DDPM implementations, providing essential properties for iterative denoising:

**Encoder-Decoder Structure:**
- **Encoder**: Progressive downsampling captures multi-scale features
- **Bottleneck**: Processes lowest resolution with highest channel count
- **Decoder**: Progressive upsampling reconstructs spatial resolution
- **Skip Connections**: Preserve fine-grained details across scales

**Channel Progression Strategy:**
```
Input → 128 channels (28×28)
     → 256 channels (14×14) 
     → 512 channels (7×7)
     → 512 channels (4×4) [bottleneck]
     → 256 channels (7×7) + skip connection
     → 128 channels (14×14) + skip connection  
     → Output channels (28×28)
```

### 2.2 Skip Connection Architecture

**Mathematical Formulation:**
```
Decoder_level_i = Upsampling(Encoder_level_i+1) + Skip_connection_i
```

**Architectural Benefits:**
1. **Gradient Flow**: Direct paths for gradients prevent vanishing gradient problems
2. **Multi-Scale Information**: Combines coarse semantic information with fine spatial details  
3. **Training Stability**: Reduces optimization difficulty by providing multiple learning paths
4. **Feature Preservation**: Maintains spatial information that might be lost in encoder compression

### 2.3 Advanced Architectural Components

**Batch Normalization Strategy:**
Applied after each convolution for training stability:
```

```

**Activation Function Selection:**

**Upsampling Strategy:**

## 3. DDPM Implementation Architecture

### 3.1 Training Pipeline Design

**Forward Process Implementation:**
```python
# Sample random timestep for each batch element
t = torch.randint(1, self.T + 1, (batch_size,))

# Get noise schedule parameters
alpha_t, alpha_bar_t = self.get_alpha(t)

# Sample noise and create noisy images
epsilon = torch.randn_like(x_0)
x_t = sqrt(alpha_bar_t) * x_0 + sqrt(1 - alpha_bar_t) * epsilon
```

**Loss Computation Strategy:**
```python
if self.denoising_objective == 'x_zero':
    x_0_pred = self.unet(x_t)
    loss = self.criterion(x_0_pred, x_0)
elif self.denoising_objective == 'epsilon':
    epsilon_pred = self.unet(x_t) 
    loss = self.criterion(epsilon_pred, epsilon)
```

### 3.2 Inference Pipeline Architecture

**Iterative Denoising Process:**
```python
# Start from pure noise
x_t = torch.randn(num_samples, *image_shape)

# Iteratively denoise
for t in range(T, 0, -1):
    alpha_t, alpha_bar_t = get_alpha(t)
    alpha_bar_t_minus_1 = get_alpha(t-1)[1]
    
    # Model prediction
    if denoising_objective == 'x_zero':
        x_0_pred = unet(x_t)
        # Compute x_{t-1} from x_0 prediction
    elif denoising_objective == 'epsilon':
        epsilon_pred = unet(x_t)
        # Compute x_{t-1} from epsilon prediction
    
    # Add noise for stochasticity (except final step)
    if t > 1:
        x_t = predicted_x_t_minus_1 + sigma_t * torch.randn_like(x_t)
```

### 3.3 Noise Schedule Management

**Buffer Registration Strategy:**
```python
# Register as buffer for automatic device handling
alpha_t_list = linear_schedule(alpha_1, alpha_T, T)
self.register_buffer('alpha_t_list', alpha_t_list)
```

**Alpha Retrieval with Broadcasting:**
```python
def get_alpha(self, t):
    alpha_t = self.alpha_t_list[t, None, None, None]  # Broadcast for [B,C,H,W]
    alpha_bar_t = torch.cumprod(self.alpha_t_list, dim=0)[t, None, None, None]
    return alpha_t, alpha_bar_t
```
